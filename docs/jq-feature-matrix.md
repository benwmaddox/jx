# jq feature matrix and jaq completeness

Generated by `tools/jqcompat.py report` from jq 1.8.2 (`tests/jq.test` at tag jq-1.8.2) and jaq 3.1.2. All decisions below are **proposals** for the owner (columns marked Decision); the class and stage columns come from docs/design.md section 6 and 9. Case-to-feature tagging is a regex heuristic over the program text (see tools/jqcompat_tags.tsv), so per-tag counts overlap and class/decision counts are estimates, not proofs.

## Summary

- `jq.test` has 550 runnable cases (19 are `%%FAIL` cases that must not compile). jq 1.8.2 itself passes 550 of 550 (harness check; module cases run with `-L` on the tag's tests/modules; cases whose comment says "Runtime error" are expected to fail at run time). Byte-for-byte match of jq output with the expected text: 444 of 531 ok-cases (the rest differ only in formatting such as key order or number text, which the test runner ignores).
- jaq 3.1.2 passes **371 of 550 (67.5%)** compared as parsed JSON; 281 of them are also byte-identical. Not passing: 80 differ, 56 fail to compile (undefined filter or syntax), 42 fail at run time with no output, 1 time out.
- 56 of jaq's 80 differing cases use `catch`, so many differences are only error-message text.
- jaq lacks 21 of 226 jq 1.8.2 builtins (name/arity): IN/1, IN/2, INDEX/1, INDEX/2, JOIN/2, JOIN/3, JOIN/4, builtins/0, format/1, fromstream/1, get_jq_origin/0, get_prog_origin/0, get_search_list/0, have_decnum/0, have_literal_numbers/0, input_line_number/0, lgamma_r/0, modulemeta/0, tostream/0, trimstr/1, truncate_stream/1.
- Biggest jaq gaps by tag are in the table of section 1 (sorted by cases failing); notable: `$__loc__`, `?//`, `tostream`/`fromstream`/`truncate_stream`, SQL-style (`INDEX`, `IN`, `JOIN`), `trimstr`, `input_line_number`, `have_literal_numbers`, number text (`1E+3` vs `1e3`) and error-message wording; command-line: `--stream`, `--seq`, `-a`, `--jsonargs`, `--unbuffered`, `-b`.
- jx classes by jq.test case (hardest feature in the program decides): A 18 (3.3%), B 392 (71.3%), C 96 (17.5%), D 44 (8.0%).
- Share of jq.test that jx could pass if exactly these decision sets were built (upper bound: needs correct output for each case): **Stage 2 only 36.2%** (199), **Stage 2+3 62.4%** (343), **+ Later 76.0%** (418), **everything except Skip 89.1%** (490). Class C features (paths, walk, tostream, assignment, dynamic keys, `..`) are what `Open`/`Skip` hold back; a subtree fallback engine would add the C share (17.5%).

## 7. What was not verified

- Tagging is heuristic: a case with several features is assigned the hardest class and decision among its tags; some tags (`arith`, `comma-alt`, `try-catch` via `?`) over-match, so coverage numbers are rough.
- Class/decision coverage is the share of cases *within* the scope, not a promise that jx output would match: jx also needs jq's error text only if the owner decides so (design 10.2).
- Only jq.test was used; tests/man.test, tests/onig.test and tests/optional.test were not run. Real jq.test also has a few directives not exercised by this runner (`%%FAIL IGNORE MSG` is treated as a must-fail case; error text is never compared).
- jaq failing to compile counts only the process exit code 3; jaq's own error classes were not split further. Spot checks and flag probes are one input each, on Windows; Linux behavior may differ.
